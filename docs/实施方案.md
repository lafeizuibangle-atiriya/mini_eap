# Mini-EAP 半导体设备自动化控制系统 —— 项目实施方案

## 1. 项目背景与目标

Mini-EAP 是一个半导体设备自动化程序（EAP）的教学级原型，模拟"设备 ↔ EAP Host ↔ 数据库 ↔ Web 报表"的完整链路：

- **设备模拟器**（Python）：模拟 2 台刻蚀机台，具备状态机、温度漂移与报警注入；
- **EAP 主控端**（C# WinForm）：设备连接管理、远程命令下发、实时状态监视、报警确认、事件入库；
- **数据库**（MySQL）：设备运行历史与报警历史，写操作全部通过存储过程完成；
- **Web 报表端**（ASP.NET Core）：生产运行记录与报警统计查询（B/S）。

系统整体覆盖 B/S 与 C/S 两种架构形态，与半导体工厂 EAP 的核心职责（设备远程控制、Recipe 管理、报警闭环、生产数据采集）一一对应。

## 2. 模块划分与职责

| 模块 | 技术 | 职责 |
|---|---|---|
| `simulator/` | Python 3 标准库 | 机台状态机（IDLE→LOADING→PROCESSING→UNLOADING）、FDC 阈值判断（腔温连续 3 周期超限触发 E1024）、TCP JSON 行协议服务 |
| `MiniEapHost/` | C# / .NET 8 WinForm | 连接设备、下发 LOAD_RECIPE / START / PAUSE / STOP / RESET 命令、实时状态面板、报警列表与确认、事件入库 |
| `WebReport/` | ASP.NET Core 8 | 运行记录查询、报警记录查询、报警统计（调用存储过程 sp_alarm_stats），MySQL 不可用时自动降级读本地事件文件 |
| `database/` | MySQL | 4 张业务表 + 4 个存储过程（sp_add_alarm / sp_clear_alarm / sp_finish_run / sp_alarm_stats）+ 演示数据 |

## 3. 实施环境要求

| 组件 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 |
| .NET SDK | 8.0 及以上 |
| Python | 3.8 及以上（无第三方依赖） |
| MySQL | 5.7 / 8.0（默认 root/123456，可用环境变量 MINIEAP_MYSQL 覆盖连接串） |

## 4. 实施步骤（概要）

1. 执行 `database/01_init.sql`、`02_procedures.sql`、`03_seed.sql` 建库；
2. 启动设备模拟器 `python simulator/device_simulator.py --port 9000`；
3. 启动主控端 `dotnet run --project MiniEapHost`，连接 127.0.0.1:9000；
4. 启动报表端 `dotnet run --project WebReport`，浏览器访问 http://127.0.0.1:5050。

详细命令与验证标准见《部署手册》。

## 5. 上线验收标准

- [ ] 主控端能连接模拟器并显示 2 台机台实时状态（状态着色正确）；
- [ ] LOAD_RECIPE → START → PROCESSING → 运行完成（run_done）全链路可用；
- [ ] 温度超限能触发报警并入库，RESET 后报警复位入库；
- [ ] Web 报表能看到运行记录与报警记录；
- [ ] 停掉 MySQL 后系统仍可运行（存储自动降级为本地文件）。

## 6. 风险与约束

- 本原型使用自定义 TCP JSON 协议简化通信；工业现场标准为 SECS/GEM（HSMS），协议模型可对应迁移；
- 数据库默认按 MySQL 实施，SQL 与存储过程为标准写法，可迁移 Oracle（JD 目标库）；
- 主控端为单机 WinForm，未做分布式部署。
